# 작업 방식 — 에이전트 역할 분담

챕터 단위로 진행한다. 메인 에이전트는 **오케스트레이터**로서 지시·장부·판정·커밋만 하고, 본문은 직접 쓰지도 검수하지도 않는다.
이 절차와 R1~R8 은 `textbook-html` skill 의 규약이다(원본: skill 의 `references/orchestration.md`).

| 역할 | 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 오케스트레이터(메인) | 메인 | 지시서 작성, 장부 관리, 판정 처리, 병렬 판단, 커밋, 보고 | 본문 집필·수정 |
| 집필 | `textbook-html:textbook-writer` | 한 장 집필(`docs/chNN.html`), `book.js` 의 `BOOK`/`TERMS` 반영, 자체 점검(probe), **수정 모드**로 BLOCK 반영 | 커밋, 다른 장 수정 |
| 검수 | `textbook-html:textbook-reviewer` | 집필자와 독립된 읽기 전용 검수, PASS/FIX 판정 | 파일 수정 |

## 진행 장부 — `authoring/03-진행-장부.md`
서브에이전트는 매번 이전 맥락 없이 시작하므로 장 사이의 약속은 파일로 넘긴다. 미결 약속·용어/기호·장별 기록(뒷장이 알아야 할 이름, 커리큘럼과 달라진 점)을 담는다.
이 repo 는 순차 진행이라 집필자가 반영하고, 오케스트레이터가 확인한다. **장부는 그 장의 커밋에 포함한다.**

## 한 장의 흐름 (순차)
1. 오케스트레이터가 지시서를 써서 집필 에이전트 호출.
2. 집필 보고를 받아 검수 에이전트(새 인스턴스) 호출.
3. **PASS** → 4. **FIX**(사유는 BLOCK 뿐) → BLOCK 목록 **원문**을 집필 에이전트 수정 모드에 전달, 재검수. 재검수 최대 2회, 2회 뒤에도 FIX 면 멈추고 사용자에게 보고.
   (필요 시 오케스트레이터 재량으로 리뷰의 사실 오기 NOTE 를 골라 같은 수정 패스에 추가할 수 있다.)
4. 오케스트레이터가 probe 를 한 번 확인하고 **커밋**.
5. 한 줄 보고(장·페이지 수·검수 라운드·커밋) 후 다음 장으로 이어 간다. 사용자가 "한 장 쓰고 멈춰"라고 했을 때만 멈춘다(R8 은 검수 PASS 로 충족).

사용자에게 묻는 경우는 2라운드 실패, 커리큘럼 수정이 필요한 발견, 정본 변경뿐이다.

**지시서에 담을 것:** skill, 교재 루트, 브라우저 절대경로, scratchpad, 장 번호, 모드(집필/수정), 병렬 여부(여기선 순차), 사용자 지정 사항, (수정) BLOCK 원문, (검수) 집필 보고 원문. 장 내용은 옮겨 적지 않는다 — 에이전트가 커리큘럼을 읽는다.

## 검수 기준
- **수학 정확성(최우선):** 모든 수식·숫자·손계산을 독립적으로 재계산한다. 관통 예제 정답
  `w=(½,½), b=−2, α=(¼,0,¼)`, 마진 폭 `2√2` 와 어긋나면 오류.
- 위젯 솔버는 독립 기준 풀이와 대조한다.
- 기획서(§1 전제, §5 서술 방침)와 커리큘럼(페이지 수·항목·`.later` 빚) 준수.
- 개념 → 이름 순서, 용어는 정의 후 사용, 기호는 처음 나올 때 뜻을 밝혔는지.
- 규약 R1~R8, `authoring.md` 의 "자주 틀리는 것".
- 기술 점검: probe(`NO-OVERFLOW screens=<값> termsMissing=0`; 점검 시 `--virtual-time-budget` 을 크게), 페이지 가로 스크롤, 헤드리스 스크린샷으로 위젯 슬라이더 조작 확인.
- 퀴즈 모든 선택지에 `data-why`, 과제 모범답안 존재.

## 커밋 규칙
- 장 하나 = 커밋 하나: `docs/chNN.html`, `book.js` 변경분, 진행 장부. 리뷰 PASS 후에만.
- 런타임(`book.css`/`book.js` 로직) 수정은 별도 커밋으로 먼저 낸다.
- 커밋 메시지는 한국어, **Co-Authored-By 라인 금지**(CLAUDE.md). 예: `6장 집필: 커널 트릭 (8페이지)`.
- `docs/` 에는 산출물만, 저자용 문서는 `authoring/`.

## 병렬화
기본은 순차이며 이 repo 는 순차로 진행한다. 병렬은 장끼리 의존이 없고, 약속이 고정되어 있고, 장당 8페이지 이상으로 이득이 클 때만 쓴다(상세: skill 의 `orchestration.md`). 판단이 서지 않으면 순차.

## 금기
- 본문을 직접 고치지 않는다(오탈자도 수정 모드로 시킨다).
- 리뷰 PASS 없이 커밋하지 않는다. 집필자의 "통과했다"로 검수를 생략하지 않는다.
- 검수 지적은 요약하지 않고 원문으로 전달한다.
