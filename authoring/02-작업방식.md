# 작업 방식 — 에이전트 역할 분담

챕터 단위로 진행한다. 메인 에이전트는 **오케스트레이터**로서 지시·판단·커밋만 하고, 본문은 직접 쓰지 않는다.

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 오케스트레이터(메인) | 에이전트 호출, 검수 지적의 수용/기각 판단, 사용자 보고, 커밋 | 본문 집필·수정 |
| 집필 에이전트 | 한 장을 집필(`docs/chNN.html`), `book.js` 의 `BOOK`/`TERMS` 반영, 기본 점검(probe) | 커밋, 다른 장 수정 |
| 검수 에이전트 | 읽기 전용으로 점검 → 지적 목록 보고 (파일 수정 금지) | 파일 수정 |
| 수정 에이전트 | 오케스트레이터가 **수용한** 지적만 반영 | 지적에 없는 부분 개선 |

## 한 장의 흐름
1. 집필 → 2. 검수 → 3. 오케스트레이터가 지적을 수용/기각으로 분류 → 4. 수용분만 수정 에이전트가 반영
→ 5. (필요 시) 재검수 → 6. 오케스트레이터가 커밋 → 7. 사용자에게 보고하고 멈춤(R8).

## 검수 기준
- **수학 정확성(최우선):** 모든 수식·숫자·손계산을 직접 재계산한다. 관통 예제 정답
  `w=(½,½), b=−2, α=(¼,0,¼)`, 마진 폭 `2√2` 와 어긋나면 오류.
- 기획서(§1 전제, §5 서술 방침)와 커리큘럼(화면 수·항목·`.later` 빚) 준수.
- 개념 → 이름 순서, 용어는 정의 후 사용, 기호는 처음 나올 때 뜻을 밝혔는지.
- 규약 R1~R8, `authoring.md` 의 "자주 틀리는 것".
- 기술 점검: probe(`NO-OVERFLOW screens=<값> termsMissing=0`), 페이지 가로 스크롤, 위젯 슬라이더 조작 스크린샷.
- 퀴즈 모든 선택지에 `data-why`, 과제 모범답안 존재.

## 커밋 규칙
- 장 단위로 커밋. 커밋 메시지는 한국어, **Co-Authored-By 라인 금지**(CLAUDE.md).
- `docs/` 에는 산출물만, 저자용 문서는 `authoring/`.
